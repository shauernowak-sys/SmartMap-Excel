# SmartMap Excel 使用说明

SmartMap Excel V0.2是Python命令行工具，用确定性规则把Excel原始明细账转换为凭证候选，再按已配置模板生成Excel。适合在明确科目映射、辅助来源和凭证范围后使用。核心运行不调用大模型API，不上传业务数据，也不连接财务系统执行导入。

## 安装与测试

需要Python 3.10及以上版本；开发验证环境为Python 3.12。建议使用虚拟环境：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m unittest discover -s tests -v
```

仓库不提供企业样本、获批业务映射、个人档案、凭证成品或敏感核对报告。依赖本地业务文件的测试会明确跳过，合成测试仍可独立运行。业务配置与合成示例分开，示例不能直接作为企业确认结果使用。

## 配置

- `config/example.json`：原始表、凭证前缀、规则审核状态、科目映射的合成示例。
- `config/auxiliary.example.json`：按目标科目核算类别配置辅助字段、档案及来源策略的合成示例。
- `config/schema.json`：配置格式及字段约束。
- `config/template.v1.json`：一种24列凭证模板的字段、类型和类别对应方式；使用前须与自己的系统模板核对。

业务配置建议放在`config/local/`。一项规则可以为candidate、confirmed或rejected。candidate只提供待审核线索，不能据此实际排除记录或选择目标科目；confirmed需审核记录及依据。

科目映射采用完整编码对应，不用字符串截取推断。层级规则在同一凭证和摘要内分别核对父子借贷金额，保留重复次数；证据不足则待确认。整凭证筛选禁止指定凭证白名单或Excel行号，支持按账期和源文件SHA-256限定规则适用范围。

`source_profile.closing_recognition`可指定收入、费用、本年利润等科目角色。损益结转识别和是否纳入迁移是两件事；整张排除需明确已确认的筛选规则，且可要求`classification_equals=closing_structure_verified`。不能仅凭摘要文字删除记录。

辅助取值优先明确编码、明确字段，最后才使用配置的科目名称提取方式。默认要求同类别档案唯一命中。若业务已确认备查仅为非完整参考，配置`name_validation_policy=source_name_reference_only`可在名称来源明确而备查缺项时保留名称；不编造编码或新增档案。歧义、编码与名称冲突、原始来源缺失仍会阻断整张凭证。

## 转换

先复制合成示例形成自己的配置，按实际业务审核后再运行。每次输出目录必须不存在。

```powershell
python -m smartmap config-check --config config/local/rules.json
python -m smartmap convert --source "本地原始明细账.xlsx" --config config/local/rules.json --out reports/conversion/new_run
python tools/verify_conversion_run.py --run reports/conversion/new_run --audit-out reports/conversion_audit.json
```

原始解析、层级证据、映射、整凭证筛选、分组平衡、月末日期和辅助核算均在本地执行。金额使用十进制核验，不自动平账；空白、零和非法金额分开记录。

退出码0表示本阶段完成；3表示存在业务待确认；2表示失败。0不表示已经在财务系统导入成功。默认只要一张凭证待确认就阻断整批导出；显式选择`--allow-partial`才能导出完整正常凭证，批次仍保留未完整通过的状态。

## 模板准备和结果输出

已填好的历史成品可用来准备空模板：程序先清除凭证数据区，保留表头、样式和备查内容。模板写出只读取这个空模板及通过审计的正式候选，禁止拿诊断结果补齐正式输出。

```powershell
python tools/export_import_template.py prepare --reference "本地已验证模板.xlsx" --profile config/template.v1.json --out outputs/template_preparation/new_run
python tools/export_import_template.py export --run reports/conversion/new_run --prepared outputs/template_preparation/new_run --out outputs/final/new_run
```

输出为`vouchers.xlsx`及来源清单。写出前检查完整凭证、连续内部序号、必填字段、字段类型及金额精度；保存后重新读取检查。科目编码统一使用文本以保留前导零，日期和金额使用真实日期及数值单元格；空白保持空白。过大精度金额拒绝输出，摘要中的等号保持为文字。

有部分导出需求时，必须在转换和模板输出两个步骤均显式选择`--allow-partial`，不能导出异常凭证中的部分分录。宏、外链、公式及尚未适配的数据区复杂对象会被拒绝，不会静默丢弃。

## 独立历史验收

仅验收阶段读取人工整理表或历史成品，不能把答案传回转换流程。比较采用多重集合保留重复次数，不假设行号天然对应。

```powershell
python tools/evaluate_conversion.py --run reports/conversion/new_run --manual "本地人工整理工作簿.xlsx" --final "本地历史成品.xlsx" --out reports/evaluation/new_run
python tools/evaluate_auxiliary.py --run reports/conversion/new_run --final "本地历史成品.xlsx" --out reports/auxiliary_evaluation/new_run
python tools/verify_import_output.py --run reports/conversion/new_run --export outputs/final/new_run --prepared outputs/template_preparation/new_run --final "本地历史成品.xlsx" --out reports/final_acceptance/new_run
```

最终文件验收核对实际保存的Excel，而非仅检查写出计划；含字段、类型、重复次数、借贷平衡、备查内容及原始行来源。每一阶段清单保留当时的状态，不回写既有报告。最终是否按参考验收通过，查看最终验收报告的`reference_acceptance_passed`。

## 项目结构与范围

`smartmap/`是转换及模板引擎，`tools/`是审计和独立验收工具，`tests/`使用合成数据并保留可选本地集成测试，`verifier/`保留V0.1源码用于历史行为审计。V0.1的artifact-tool依赖不是V0.2核心运行依赖。

当前为已完成真实案例验证的命令行版本，尚无面向财务人员的完整图形操作流程。其他月份、其他企业和不同模板需要各自配置及验收；不会自动套用某次历史确认。
